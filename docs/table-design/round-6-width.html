Tables · Round 6 — width, overflow & the sticky guard

Round-4's fit-content amendment raised the real question: how does a table relate to the three-rung ladder (Column 42 / Wide 66 / Full 80rem)? Both schemes below center the panel; they differ in whether widths are continuous or stepped. The dashed guides are the actual rungs — widen the window to see them all. One honest constraint up front: CSS cannot measure a table's natural width to auto-snap it to a rung, so stepped widths must be chosen at build time (a zola-plus directive argument, defaulting to Column) — continuous needs no authoring at all.

6C — equal-step scale snap up to the next 6rem step — below the column and above it

The scale is …, 18, 24, 30, 36, 42, 48, 54, 60, 66, 72, 78, capped at 80 — every 6rem, passing exactly through the old rungs. Snapping is automatic (calc-size() measures the table), so unlike 6B nothing is authored. Support today: Chrome snaps; Safari/Firefox get the continuous 6A behaviour as a built-in fallback.

Part C — the sticky coverage guard sticky must never own the screen

Your rule — "not sticky if it covers too much of the screen" — can't be done in pure CSS as an on/off switch (measuring the column's share needs JS). The CSS-only equivalent attacks the cause instead: the sticky column is clamped to 40% of the container (40cqw) and wraps, so it can never cover more than that, on any screen. Long labels below; drag the sample to see the clamp track the container.

Un-clamped, the first column here would take ~65% of a phone screen and sticky would feel like a wall. Clamped, the label wraps to at most 40% and the data keeps the rest. If even 40% feels like too much for a given table, that table shouldn't be sticky at all — which stays an authoring choice (scroll vs scroll: sticky).

  • S — sticky guard: clamp at 40cqw as shown (or another share), sticky remaining opt-in per table?
