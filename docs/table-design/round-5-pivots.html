Part A — where reflow works, and where it fails

5·1 — reflow at its best record-shaped rows: each row is one thing

Rows are records (a field and its attributes); nobody compares down a column. Cards lose nothing. This is the reflow sweet spot: label:value semantics, ≲ 8 rows, prose-ish cells.

A matrix is read across both axes — "which guest builds slowest?" Narrow, that question now takes three cards and your short-term memory: the column is gone, and with it the comparison. Reflow also repeats every label per row (verbose past ~8 rows) and gives up numeric alignment. Matrices should keep their grid — that's scroll, below.

Scroll's weaknesses: panning is invisible without an affordance (the cut-off column edge is the only hint), and once you pan, the first column — the row's identity — scrolls away. A sticky first column fixes the second problem for exactly the tables scroll is right for. It needs an opaque background (here the panel token), which shows as a subtle seam while panning.

Part C — transpose & expand the other two, briefly

Transpose (left → right) trades width for height: good when a table is much wider than it is tall (many columns, ≤ 4 data rows) — each row becomes a column, so past ~4 rows the transposed form overflows again and you're back where you started. Expand is the last resort: a table too big even for the Full rung stays clipped and opens full-bleed via the :target overlay (live on /design-ladder). Both already work in zola-plus; their skin just inherits this system.

Part D — grouped rows first complex variant

A group header row spans the table and speaks the column-header voice; wide it reads as a section rule, narrow it becomes a heading between cards — the pivot survives it because the group row carries no data labels. Markdown pipe tables can't express this, so it is a zola-plus convention (decided): a body row whose cells after the first are all dashes — | **sync behaviour** |-------|-------| — becomes a spanning group header, echoing the delimiter row so the source itself reads as a section divider.

Decided

  • P1 ✓ — the shape map: when a table is too wide, its shape picks the escape hatch — self-contained rows → reflow · few rows × many columns → transpose · compare-both-ways numbers → scroll · too big even for Full → expand.
  • P2 ✓ — grouped rows via the dash-row convention (| **group** |-------|-------|).
  • P3 — superseded: sticky is decided per table by the measured policy in round 6 (6rem budget, ≤2-line labels, else not sticky).
